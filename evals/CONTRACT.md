# Task and grader contract, version 2

The executable contract is `src/contract.ts`. A suite exports `suite: TaskSuite` from `evals/tasks/index.ts`: its task families and its tasks. That suite holds one neutral example task, `report-version`. Task code must not import provider or runner internals.

A family names the limits its tasks run under: `wallSeconds`, `toolCalls`, `outputBytes`, and optionally `maxTurns` and `budgetUsd`. A task names its `family`, its selection `tags`, the harness prompt it starts from (`prompt`, default `task`) and its fixed `followUps`, the user's later messages, sent in order after each answer. A campaign can change a family's limits and override the prompt and the built-in skill files per arm; task code never sees those overrides.

The runner creates a fresh host `world` and mounts it at `/world` in a networkless Linux task container. `context.exec({argv, cwd})` executes argument arrays there with `HOME=/world/home`, `TACK_STATE_DIR=/world/state`, controlled Git/XDG/temp configuration, and `tack` on PATH. Every supplied cwd must be under `/world`. Setup may write files below host `context.world`; agents see only the container paths. Do not write host paths into fixture content or prompts. The executable is a compiled Linux Tack artifact, not source mode. Every task must work with that build.

`prepare` establishes state, verifies initial conditions and returns the task's `request`, its container cwd and public facts. The trial's prompt template places the request at `{{request}}` and the cwd at `{{cwd}}`. `oracle` runs in a separate fresh fixture and returns command evidence plus its final answer. The runner grades the oracle and rejects a task without a passing oracle before any paid request. `grade` observes final state through contained commands and returns exactly one result per declared criterion and violated invariants. Weights sum to one, unknown earns no credit, required criteria and all invariants must pass. Exit zero alone proves no task outcome. Task authors test criterion mutations and scope preservation. No credentials are needed for preparation, oracle or grading.

Agent command evidence comes from the trusted task tool bridge, not text guessed from native events. Prompts should request `final-answer.json` only when helpful; final text is available to graders. Hidden expected facts stay in task code or closures on the host. The agent container never mounts that code, the result store, host home or Docker socket. Agent built-in tools are disabled; its one MCP shell tool executes in the separate networkless task container. This controlled MCP bridge is the sole exception to the original no-MCP design, and is part of the recorded enforcement conditions.

An arm names one campaign variation of the agent input: the prompt, the built-in skill files, or both. The planner runs every arm with the same build, task, seed, limits and graders, and alternates their order across repetitions. New providers implement the driver contract, not new task definitions.

The runner delivers the selected image's built-ins, with the arm's skill overrides applied, through a read-only `/instructions/` mount, and mounts the same copy over the image's built-ins so that `tack` links those files too. It creates no instruction files inside `/world`, so the instructions do not change the logical fixture snapshot. Every delivered file receives a SHA-256 digest in the trial evidence.
