# Add a source

A source is a folder you own that holds skills, commands, context, docs or scripts, with a
`tack.yaml` at its top that says where each kind lives. Tack reads the folder where it is: it
never moves or copies your files. Register each folder once; every project then picks from it.

Run `tack init` once first, as [Get started](../getting-started) shows. It creates Tack's state,
enables the agents it finds and links the built-in skills. If you skip it, the first `source add`
that registers creates the state and enables the agents it finds, and says so in a note.

This guide registers two sources: `~/agent-setup`, a folder of your own without a `tack.yaml`, and
`~/code/acme-agent-skills`, a team repository that already has one.

## A folder without a tack.yaml

Say your folder looks like this:

```text
~/agent-setup
├── commands/ship.md
├── handbook/release-process.md
└── skills
    ├── debug-flaky-test/SKILL.md
    └── pr-review/SKILL.md
```

Write its `tack.yaml` as JSON: the same keys and values, here in `~/agent-setup.json`. Each entry
names a folder inside the source by what it holds, and `version` and `name` are required:

```json
{
  "version": 1,
  "name": "agent-setup",
  "skills": [{ "path": "skills" }],
  "commands": [{ "path": "commands" }],
  "docs": [{ "name": "handbook", "path": "handbook" }]
}
```

Pass it with `--config`. Tack checks it as `tack check` would, previews the `tack.yaml` it would
write and what each folder holds, and changes nothing:

<Terminal
  commands={["tack source add ~/agent-setup --config ~/agent-setup.json"]}
  output={previewOutput}
/>

Check that every skill, command and docs folder you expect is listed. A file that does not parse is
left out: the preview then reads `! partial` and lists the file under `Problems`. A mistake in the
JSON, such as an unknown key or a missing `name`, fails the preview: Tack lists every problem at
once, each with its field and its line in the JSON. Then apply it: Tack reads the JSON again,
writes the `tack.yaml` and registers the source. It never writes over a `tack.yaml` that exists.

<Terminal
  commands={["tack source add ~/agent-setup --config ~/agent-setup.json --apply"]}
  output={applyOutput}
/>

To skip the file, write `--config -` and pass the JSON on standard input, with a heredoc for
instance. Pipe the same JSON again with `--apply`:

```sh
tack source add ~/agent-setup --config - <<'EOF'
{"version": 1, "name": "agent-setup", "skills": [{"path": "skills"}], "commands": [{"path": "commands"}]}
EOF
```

The JSON takes every key a `tack.yaml` takes: scripts, `include` and `exclude` patterns,
`depends-on`, `maintainers` and the rest, except `imports`. `tack guide tack-yaml` lists them. The
config must be JSON: YAML fails with `config-not-json`. Tack writes the `tack.yaml` from what it
read, so the file holds plain YAML whatever the layout of your JSON.

Run `tack source add ~/agent-setup` without `--config` and Tack refuses with
`declaration-config-required`. It reads the top of the folder and suggests a JSON declaration for
the folders it recognises by name, here `skills` and `commands`; add the `handbook` docs yourself.
Its `Next` is `tack guide tack-yaml`.

When the skill folders sit at the top of the folder, such as `~/skills/review/SKILL.md`, declare a
skills collection instead: `{"version": 1, "name": "skills", "kind": "skills"}`. Its `tack.yaml`
holds `kind: skills` and the name, nothing else. A folder of commands or docs beside it is then a
source of its own, with `"kind": "commands"` or `"kind": "docs"`. Until it is, the preview warns
`collection-folder-not-skill` about that folder and leaves it out; the warning changes nothing
else.

## A folder that already has a tack.yaml

A folder with a `tack.yaml` previews like any other: `tack source add ~/code/acme-agent-skills`
shows the name the source takes and what it holds. Apply it to register the source; registering
writes nothing into the folder and links nothing. This is how you add a team repository you cloned.
`--config` on such a folder fails with `declaration-exists`: edit its `tack.yaml` instead.

<Terminal commands={["tack source add ~/code/acme-agent-skills --apply"]} output={teamOutput} />

Its `tack.yaml` is a skills collection with a name and its maintainers:

```yaml
version: 1
name: acme
kind: skills
maintainers:
  - platform-team
```

The `name` is the label you and other sources type, as in `acme:release-notes`. Every `tack.yaml`
needs one: Tack never takes the label from the folder, which can be called differently on each
machine. Commit the `tack.yaml` of a repository you share, so every teammate gets the
same source.

## Check it

`tack check` reads a source without registering it, and reports each problem by file and line. Run
it after every edit to a `tack.yaml`:

<Terminal commands={["tack check ~/agent-setup"]} output={checkOutput} />

Once the source is registered, edit its `tack.yaml` directly. Your agent's built-in
`manage-tack-sources` skill knows the format, and `tack guide tack-yaml` lists every key.

## Deliver it

Registering links nothing. Links go into a project, so Tack needs one: if you have not registered a
project yet, do it from inside the repository. It writes no link either:

```sh
cd ~/code/app
tack project add app
```

A source's skills and commands are on by default for every project, so preview the links for every
project and for you, then apply:

```sh
tack sync --all
tack sync --all --apply
```

With no project registered, the preview plans nothing: at user level a skill is opt-in until you
pick it. With no agent enabled, it plans nothing either, and warns `no-adapters-enabled`: run
`tack init` to enable the agents it finds. A skill can be opt-in for projects too: it then reaches a project only once you pick it.
See [Choose what each project gets](./choose-skills). The `handbook` docs are not linked by a sync
alone: attach them first, as [Link docs into a project](./link-docs) shows.
