# Choose what each project gets

Every project starts with the skills and commands its sources turn on by default. A pick changes
that for one target: one project with `--project`, or your user folders with `--user`. A pick saves
at once and links nothing; `tack sync` then previews the links it calls for.

| Command                                           | What it does                                            |
| ------------------------------------------------- | ------------------------------------------------------- |
| `tack pick include triage-issue --project app`    | Selects a skill for one project, even an opt-in one     |
| `tack pick exclude incident-report --project app` | Keeps a default skill out of one project                |
| `tack pick include commit-message --user`         | Links a skill into your user folders, for every project |
| `tack pick remove incident-report --project app`  | Forgets the pick, so the source's default applies again |
| `tack pick remove commit-message --user`          | Forgets a user pick                                     |
| `tack pick`                                       | Lists every pick, for each project and for you          |

## Keep a skill out of a project

The project `app` gets `incident-report` from the team source, but it has no use for it. Exclude it:

<Terminal commands={["tack pick exclude incident-report --project app"]} output={excludeOutput} />

The sync preview removes its links, with the reason `deselected`:

<Terminal commands={["tack sync --project app"]} output={excludeSyncOutput} />

Apply it with `tack sync --project app --apply`. Excluding a skill that another selected skill
requires blocks that skill too, and the preview names the blocker.

## Add an opt-in skill to a project

An opt-in skill reaches a project only once you include it, as
[Write a skill](./write-a-skill#4-link-it) shows for `triage-issue`. See every pick at once:

<Terminal commands={["tack pick"]} output={pickListOutput} />

## Use a skill everywhere

A skill you want in every repository belongs in your user folders, such as `~/.claude/skills`.
Every agent loads it in every project, registered or not:

<Terminal commands={["tack pick include commit-message --user"]} output={userPickOutput} />

`tack sync --all` previews your user folders and every project together. A project does not keep a
link of its own to a skill your user folders already hold, so each agent lists it once: the preview
removes those project links with the reason `linked-for-user`.

<Terminal commands={["tack sync --all"]} output={userSyncOutput} />

Apply it with `tack sync --all --apply`. To undo it, run `tack pick remove commit-message --user`:
the next `tack sync --all` removes the user links and links the skill back into each project that
selects it.

Some agents read only project folders, or only user folders, so a user pick does not reach every
agent; [Agent support](../agent-support#agents-reached-through-a-shared-folder) marks them.

## See what a project gets

`tack status --details` lists every link, what each agent gets and why, and the lines for
`.gitignore` when the project ignores its links:

<Terminal commands={["tack status --project app --details"]} output={statusOutput} />

## Browse in the terminal

`tack explore --project app` opens the explorer: every resource with its state in the project, such
as `● default`, `● included` or `○ opt-in`. Stage picks and docs with `i`, `x` and `a`, review the
sync, then confirm. It needs an interactive terminal; agents use `tack catalog`, `tack pick` and
`tack status` instead.
