# Link docs into a project

Docs live in a source, like skills. Attach them to a project and every worktree of the project gets
a link to them under `.tack/docs`, so your agents read and search the same files you edit. You read
them in a local reader.

This guide links the `handbook` folder of `~/agent-setup` into the project `app`.

## 1. Declare the docs

A source declares each docs folder by name in its `tack.yaml`. `tack source add --docs handbook`
writes this entry for you, as [Add a source](./add-a-source) shows; in an existing `tack.yaml`, add
it by hand:

```yaml
docs:
  - name: handbook
    path: handbook
```

Any Markdown or MDX file in the folder is a document. Frontmatter such as `title`, `type`, `status`
and `tags` shows in search hits and in the reader's filters:

```markdown
---
title: Release process
type: guide
status: active
tags: [release]
---
```

## 2. Attach and mount

Attach the docs to the project. Like a pick, this saves at once and links nothing:

<Terminal commands={["tack docs attach handbook --project app"]} output={attachOutput} />

`--no-adapters` limits the sync to docs, so the preview shows only the mount:

<Terminal commands={["tack sync --project app --no-adapters"]} output={syncOutput} />

<Terminal commands={["tack sync --project app --no-adapters --apply"]} output={applyOutput} />

A plain `tack sync --project app` plans the docs mounts and the agent links together. The path
holds the source's registration ID, so two sources can each have a `handbook`.

The mount is a link to a folder on your machine, and its path differs on every machine, so Git shows
`.tack/` as untracked. Ignore it in the repository's `.gitignore`.
`tack status --project app --details` prints this line under "For .gitignore in project app",
beside the lines for agent links:

```text
/.tack/
```

## 3. See what is attached

<Terminal commands={["tack docs --project app"]} output={docsOutput} />

## 4. Search

`tack docs search` reads every attached document without starting a server. Each hit names the
file and the lines it came from, so an agent can open the exact passage:

<Terminal commands={['tack docs search "hotfix" --project app']} output={searchOutput} />

Narrow it with `--type`, `--status`, `--tag` and `--limit`.

## 5. Read in the browser

`tack docs serve` starts the reader and opens it in your browser. It shows every attached source in
one view, with search and metadata filters, and reloads when you save a file. It runs until you
press Ctrl+C.

<Terminal commands={["tack docs serve --project app"]} output={serveOutput} />

`--port` picks the port, and `--no-open` keeps the browser closed.

## Detach

`tack docs detach handbook --project app` forgets the attachment. The next
`tack sync --project app --no-adapters --apply` removes the mounts; your docs stay where they are.
