# Add a worktree or clone

A project is a Git repository, and Tack links every worktree of it the same way: the picks belong
to the project, not to a folder. A worktree you add later needs one refresh and one sync.

This guide adds the worktree `~/code/app-hotfix` to the project `app`.

## A new worktree

Create the worktree with Git, then go into it:

```sh
git -C ~/code/app worktree add ~/code/app-hotfix -b hotfix
cd ~/code/app-hotfix
```

`tack project refresh` finds the project from the worktree's Git folder and previews the new root,
with the docs mounts it gets:

<Terminal commands={["tack project refresh"]} output={refreshOutput} />

<Terminal commands={["tack project refresh --apply"]} output={refreshApplyOutput} />

Inside a registered root, a bare `tack sync` selects its project. The preview creates the new
worktree's links and leaves the others as they are:

<Terminal commands={["tack sync"]} output={syncOutput} />

Apply it with `tack sync --apply`. `tack doctor` warns about a worktree that refresh has not added
yet.

## Remove a worktree

Git refuses to remove a worktree that holds untracked files, and Tack's links are untracked unless
the repository ignores them. Remove it with `--force`, then drop its root from the project:

```sh
git -C ~/code/app worktree remove --force ~/code/app-hotfix
tack project refresh --project app --apply
```

The refresh forgets the root and the links Tack had recorded in it.

## A separate clone

A clone is a repository of its own, so it is a project of its own. Register it under a new name
from inside it, then sync it:

```sh
cd ~/code/app-review
tack project add app-review
tack sync --project app-review
tack sync --project app-review --apply
```

## Let agents do it

An agent that starts in a fresh worktree can run these steps itself. `tack guide agent-instructions`
prints a section for the repository's `AGENTS.md`, and where it goes when the repository also has a
`CLAUDE.md`. With `PROJECT` replaced by the project's name, the section reads:

```md
<!-- tack-block v1 -->

## Tack

This repository's agent skills and docs come from Tack (project `PROJECT`). Before you work in a
new clone or worktree, load the `prepare-tack-checkout` skill. Without it, run from the
repository root: `tack project refresh --apply`, then `tack sync` and `tack sync --apply`. In a
clone Tack does not know, run `tack project add PROJECT` first. If `tack` is missing, tell the
user: it installs with `npm install --global @tackup/cli`.
<!-- /tack-block -->
```

The section names no path of your machine, so it is safe to commit. The built-in
`prepare-tack-checkout` skill it names holds the steps above.
