# Share a fixed set with a profile

Picks drift: each teammate includes and excludes what suits them. A profile is a file in a source
that lists the exact skills, commands and docs a project gets. You review it like any other change,
and whoever applies it gets that set and nothing else, until they apply another one.

This guide saves what the project `app` uses as the profile `reviewer`, applies it to the project
`ci`, then carries it in one file to a CI runner that has never seen the sources.

## 1. Save what you use

`tack profile save` previews the profile file it would write from what a project uses now, its
defaults and picks, and the change to the source's `tack.yaml`, which moves to version 2 to
publish it:

<Terminal
  commands={["tack profile save ~/agent-setup reviewer --project app"]}
  output={saveOutput}
/>

Apply it with the same command and `--apply`. It writes only the profile and its entry in
`tack.yaml`; the picks and links of `app` stay as they are. Built-in skills are never members:
every machine gets them anyway.

Then check the profile, with every source its members come from:

<Terminal commands={["tack check ~/agent-setup ~/code/acme-agent-skills"]} output={checkOutput} />

Commit the profile and the `tack.yaml`, and push them, as for any change to the source.

## 2. Apply it to a project

`tack profile apply` previews the profile's exact list at one explicit target. Here the project
`ci` is a separate clone of the repository at `~/ci/app`, registered with `tack project add ci`:

<Terminal
  commands={["tack profile apply agent-setup:reviewer --project ci --target-root ~/ci/app"]}
  output={applyOutput}
/>

The preview is `partial` because Claude Code and Codex take no commands, so `ship` reaches Cursor
only. Apply it:

```sh
tack profile apply agent-setup:reviewer --project ci --target-root ~/ci/app --apply
```

Repeat `--target-root` for every worktree of the project. A project that already has picks or
links needs `--force` to replace them. From now on the project's set is fixed: a pick is refused,
and `tack status` and `tack doctor` name the profile.

<Terminal commands={["tack pick include incident-report --project ci"]} output={fixedOutput} />

To change the set, edit the profile, commit it, and apply it again.

## 3. Carry it to another machine

A CI runner or a container may have no copy of your sources. `tack profile export` packs the
profile's files into one `.tar.gz` with a checksum for each. It previews first; `--apply` writes
it, and never over an existing file. The list of files is cut short here:

<Terminal
  commands={["tack profile export agent-setup:reviewer reviewer.tar.gz --apply"]}
  output={exportOutput}
/>

Docs and scripts travel only once the source says what they need: an entry under `bundle-support`
in `tack.yaml`. Without one, the preview stops with `profile-bundle-incomplete` and names the
resource. Docs with no files outside their folder need an empty list:

```yaml
bundle-support:
  - kind: docs
    name: handbook
    complete: true
    files: []
    prerequisites: []
```

On the other machine, read the bundle before you apply it, and validate it:

```sh
tack profile inspect-bundle reviewer.tar.gz
tack check reviewer.tar.gz
```

Then set Tack up, register the repository and apply the bundle. No source is registered and
nothing is fetched: Tack keeps the bundle's files in its state and links them.

```sh
tack init
cd ~/app
tack project add ci
tack profile apply-bundle ~/reviewer.tar.gz --project ci --target-root ~/app
tack profile apply-bundle ~/reviewer.tar.gz --project ci --target-root ~/app --apply
```

<Terminal
  commands={[
    "tack profile apply-bundle ~/reviewer.tar.gz --project ci --target-root ~/app --apply",
  ]}
  output={bundleOutput}
/>

The bundle's sources get labels that start with `bundle-`, so they never mix with a source of the
same name on that machine. No script, hook or installer in a bundle runs while it is applied.
