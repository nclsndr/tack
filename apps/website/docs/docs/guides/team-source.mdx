# Get a teammate's new skill

A team source is a Git repository that each teammate clones and registers once, as in
[Add a source](./add-a-source). Tack never pulls for you: it links what is on disk. So a change from
a teammate reaches you in two steps, `git pull` and, for a new skill, `tack sync`.

This guide uses the team source `acme` at `~/code/acme-agent-skills`, registered on this machine,
and the project `app`. A teammate has pushed a new skill, `release-notes`.

## 1. Pull the source

```sh
cd ~/code/acme-agent-skills
git pull
```

An edit to a skill you already have is now live in every agent: each link points at the folder you
just pulled, so there is nothing more to do.

## 2. See what is missing

A new skill has no link yet. `tack status` names it for each agent of the project:

<Terminal commands={["tack status --project app"]} output={statusOutput} />

`tack catalog` lists it among the skills of `acme`, with its description.

## 3. Preview and apply the sync

The new skill follows its source's activation: a skill without Tack metadata is on by default, so
every project that uses the source gets it. Preview every project and your user folders at once:

<Terminal commands={["tack sync --all"]} output={syncOutput} />

The preview shows only what changes. Apply it:

<Terminal commands={["tack sync --all --apply"]} output={applyOutput} />

Each agent's folder in the project now holds a link back to the team repository:

<Terminal commands={["ls -l ~/code/app/.claude/skills"]} output={linksOutput} />

When the new skill is opt-in, the preview plans nothing for it: include it where you want it, as
[Choose what each project gets](./choose-skills) shows.

## When a teammate deletes a skill

After the pull, the links to a deleted skill point at nothing. The same `tack sync --all` preview
removes them, with the reason `source-missing`. Here, on a machine with Claude Code and Codex, a
teammate deleted `incident-report`:

<Terminal commands={["tack sync --all"]} output={removedOutput} />

Apply it with `tack sync --all --apply`. A renamed skill shows up the same way: the old name's links
go, with `source-missing`, and the new name's links are created.

A pick names a skill by its name, so a pick on the old name no longer applies after a rename. If you
had included or excluded the skill, `tack pick` still lists the old name: pick the new name, such as
`tack pick include incident --project app`, and forget the old one with
`tack pick remove incident-report --project app`.

## When the project ignores its links

A link is a file to Git. When a project ignores its links instead of committing them, each new skill
needs its own line in `.gitignore`. `tack status --project app --details` prints the lines under
"For .gitignore in project app"; add the new ones. Tack never edits `.gitignore`.
