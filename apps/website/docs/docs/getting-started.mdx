# Get started

Tack needs Node 22.12 or later, or Bun. It links your files into each agent; it never moves or
copies them.

<Human>
  The quickest start is one prompt. Paste it into your coding agent:

> Install Tack with `npm install --global @tackup/cli`, then run `tack guide onboarding` and follow
> it to set up my machine: ask me which folders hold my skills, commands or docs and which projects
> to link, explain each step, show me its preview, and wait for my yes before you apply it or run
> any other command that writes without a preview.

</Human>

<Agent>
  If a person asked you to set up Tack, run `tack guide onboarding` and follow it. It prints the
  onboarding guide of the installed version. Show the person each step's preview, and add `--apply`
  only after they agree.
</Agent>

## 1. Install and set up this machine

`tack init` sets up Tack at once and prints what it did: its state in `~/.tack`, the agents it found
(Claude Code, Codex, Cursor, GitHub Copilot CLI, Gemini CLI, Cline, OpenCode, Pi) and Tack's own skills linked into each. Running it again changes
nothing.

<Terminal commands={["npm install --global @tackup/cli", "tack init"]} />

Skills you made by hand in `~/.claude/skills` and similar folders are listed and left alone.

## 2. Register your skills

Tell Tack what your folder holds. Write its `tack.yaml` as JSON, with a `version`, a `name` and
the folder of each kind inside it, and pass it with `--config -` on standard input, or with
`--config FILE`. Tack previews the `tack.yaml` it would write and what each folder holds, and
writes it only when you add `--apply`. Check that the list matches every skill you expect.

<Terminal commands={[sourceAddCommand]} output={sourceAddOutput} />

When the preview looks right, pipe the same JSON again with `--apply` to write the `tack.yaml` and
register the source:

<Terminal commands={[sourceApplyCommand]} />

When your skill folders sit directly in the folder, such as `~/skills/review/SKILL.md`, declare a
skills collection instead: `{"version": 1, "name": "skills", "kind": "skills"}` gives a
`tack.yaml` that holds `kind: skills`. A folder of commands or docs beside them is then a source
of its own, with `"kind": "commands"` or `"kind": "docs"`. When you run `tack source add` on a
folder without `--config`, Tack reads the top of the folder and suggests a JSON declaration that
fits what it finds there. `tack guide tack-yaml` lists every key the JSON takes, scripts included.

A folder that already has a `tack.yaml`, such as a team repository you cloned, previews too:
`tack source add ~/code/acme-agent-skills`, then the same command with `--apply`. In a repository
you share, commit the `tack.yaml` that Tack writes, so others get the same source. Repeat this
section for each folder of skills. To change a source later, edit its `tack.yaml`; your agent's
`manage-tack-sources` skill knows how.

Every agent gets your skills. Commands reach Cline, Cursor, OpenCode and Pi only: Claude Code,
Codex, GitHub Copilot CLI and Gemini CLI have no Markdown commands folder Tack links into, and the
`tack sync` preview names the agents a selected command does not reach. Cline runs a command as
`/NAME.md`, extension included. Context is not
selected unless you pick it, and even then reaches no agent, because no agent has a folder Tack can
link it into.

## 3. Link them into a project

From inside the project's repository, register it, preview the plan, then apply it. `project add`
registers the project at once and writes no link; `tack project remove app` undoes it.

```sh
cd ~/code/app
tack project add app
tack sync --project app
tack sync --project app --apply
```

Each link points back to your file:

<Terminal commands={["ls -l .claude/skills"]} output={linksOutput} />

Repeat this section for each project. After you register another folder of skills, run
`tack sync --all` and then `tack sync --all --apply`, so every project gets its skills.

The links point to a folder on your machine, so a committed one would not work in a teammate's
clone. Ignore them and commit the `.gitignore`. Tack does not edit `.gitignore`; `tack status --project app --details` prints
the lines to add under "For .gitignore", one per link; create `.gitignore` if the repository has
none. A link is a file to Git, so a line has no trailing `/`, and each skill you link later needs
its own line.

## 4. Check

```sh
tack doctor
```

After every Tack upgrade, run `tack init` to relink Tack's own skills.
