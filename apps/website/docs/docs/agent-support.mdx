# Agent support

Tack reaches an agent in one of two ways. Eight agents have an adapter of their own: Tack links
into their folders, and four of them also get commands. Nineteen more read skills from a folder an
adapter already fills, `.agents/skills` from the Codex adapter or `.claude/skills` from the Claude
Code adapter, so they get skills once that adapter is enabled.

A project folder sits at the root of every worktree of a registered project, and Tack fills it with
`tack sync --project NAME`. A user folder sits in your home, every project's agent loads it, and
Tack fills it with `tack sync --user`. A dash means the agent does not read that folder.

## Agents with an adapter

Every adapter links skills, into a project folder and a user folder:

| Agent              | Adapter    | Skills, project    | Skills, user                |
| ------------------ | ---------- | ------------------ | --------------------------- |
| Claude Code        | `claude`   | `.claude/skills`   | `~/.claude/skills`          |
| Cline              | `cline`    | `.cline/skills`    | `~/.cline/skills`           |
| Codex              | `codex`    | `.agents/skills`   | `~/.agents/skills`          |
| Cursor             | `cursor`   | `.cursor/skills`   | `~/.cursor/skills`          |
| Gemini CLI         | `gemini`   | `.gemini/skills`   | `~/.gemini/skills`          |
| GitHub Copilot CLI | `copilot`  | `.github/skills`   | `~/.copilot/skills`         |
| OpenCode           | `opencode` | `.opencode/skills` | `~/.config/opencode/skills` |
| Pi                 | `pi`       | `.pi/skills`       | `~/.pi/agent/skills`        |

Four adapters also link commands, as the same Markdown file:

| Agent    | Adapter    | Commands, project       | Commands, user                | The agent calls them |
| -------- | ---------- | ----------------------- | ----------------------------- | -------------------- |
| Cline    | `cline`    | `.clinerules/workflows` | `~/Documents/Cline/Workflows` | workflows            |
| Cursor   | `cursor`   | `.cursor/commands`      | `~/.cursor/commands`          | commands             |
| OpenCode | `opencode` | `.opencode/commands`    | `~/.config/opencode/commands` | commands             |
| Pi       | `pi`       | `.pi/prompts`           | `~/.pi/agent/prompts`         | prompt templates     |

`tack init` enables an adapter when the agent's home folder exists: `~/.claude`, `~/.cline` or
`~/Documents/Cline`, `~/.codex` or `~/.agents`, `~/.cursor`, `~/.gemini`, `~/.copilot`,
`~/.config/opencode` or `~/.pi`. `tack adapter enable` adds one at any time.

What to know about each:

- **Claude Code, Codex, Gemini CLI and GitHub Copilot CLI get skills only.** Copilot CLI reads
  Markdown commands only from Claude Code's `.claude/commands`, and Gemini CLI reads commands only
  as TOML files. The `tack sync` preview names the agents a selected command does not reach.
- **Cline** calls commands workflows and runs a linked one as `/NAME.md`, extension included.
- **Pi** calls commands prompt templates. It reads a project's `.pi` folders from the folder it
  starts in, so start it at the project root, and it loads project resources only after you trust
  the project. Run `/reload` in Pi to see a new link.
- **Cursor** also reads `.agents/skills`, and, when its _Include Third-Party Plugins, Skills, and
  Other Configs_ setting is on, `.claude/skills` and `.codex/skills`. Cursor 3.17 and later lists a
  skill it reaches through several of these folders once.
- **Another agent's folder.** Cursor and OpenCode also read `.claude/skills` and `.agents/skills`;
  Pi, Gemini CLI and Copilot CLI read `.agents/skills`; Copilot CLI and Cline also read
  `.claude/skills`. Because each link points at the same skill folder, these agents list the skill
  once, but Gemini CLI warns of a skill conflict when the Codex and Gemini CLI adapters both link
  it, and turning one adapter off can leave the skill visible through another.
- **Standard folders only.** Tack does not follow `XDG_CONFIG_HOME` or `OPENCODE_CONFIG_DIR` for
  OpenCode, `PI_CODING_AGENT_DIR` for Pi, `COPILOT_HOME` for Copilot CLI, `GEMINI_CLI_HOME` for
  Gemini CLI or `CLINE_DIR` for Cline.
- An open agent session can need a restart to see a new link.

## Agents reached through a shared folder

These agents have no adapter. Their own docs or source say they read skills from `.agents/skills`,
which the Codex adapter fills, or `.claude/skills`, which the Claude Code adapter fills: enable
that adapter with `tack adapter enable codex` or `tack adapter enable claude`. They get skills
only; commands reach an agent only through its own adapter.

A "Project only" agent sees your skills only through a project's links, so a skill you pick with
`--user` does not reach it. A "User only" agent sees only the links in your home, so pick a skill
for it with `tack pick include NAME --user`.

## Agent versions

The folders above come from each agent's own docs or source, linked in the table, as they read when
the adapter or the row was added. Tack records no agent version for them, and vendors move these
folders often: read the agent's docs before you rely on one, and check what Tack linked with
`tack status --project NAME --details`.
