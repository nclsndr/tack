# How relay is built and run

`relay` is a command-line tool that ships as a release directory, not a single file. This page follows one release from a commit to an active install, shows what lands on disk, and names the process that runs each command. Paths in `code font` are relative to the relay repository unless they start with `~`.

## The short version

**What happens when you build.** `relay release --apply` takes a commit, exports it to a scratch directory, runs the test suite there, builds a *release directory*, runs a second gate against that directory, and only then points `current` at it.

**Why it is not one file.** The executable (`bin/relay`) is a runtime with relay's code compiled into it. It cannot carry everything:

- Plugins are run by *a second process*, started from the same executable, that loads files from disk.
- The preview server needs its own sources and `node_modules`, including native addons.
- The bundled templates must sit at one stable path that other tools can point at.

**What runs what.**

| Thing you ask for | Who runs it | Where its code comes from |
| --- | --- | --- |
| Any `relay` command | The compiled executable, in process | Bundled inside the executable |
| `relay plugin run` | A fresh child: the same executable acting as a plain runtime, running `worker.js` | The worker is in the release. The plugin and its `node_modules` come from the project. |
| `relay preview` | A child: the same executable acting as a plain runtime, running `engine.ts` | `engine.ts` and `node_modules` are in the release. Pages come from the project. |

Nothing outside `staging/` changes until the gate passes, so a failed build leaves the active release alone. A commit that fails the gate is *held*: relay will not retry it until HEAD changes or you pass `--force`.

```tree

  bin/
    relay -> ../share/relay/current/bin/relay  # created once, never rewritten
  share/relay/

    previous -> releases/<older>               # what a rollback activates [temp]

      <older>/                                 # the release before
      1.4.0/                                   # one immutable release [key] [180 MB]

        worker.js                              # the plugin worker, bundled [200 KB]
        packages/preview/src/                  # the preview engine, as source
        templates/                             # the bundled templates [24 KB]
        node_modules/                          # production deps, mostly the preview [120 MB]
        package.json                           # with the lockfile
        release.json                           # stamp, commit, builtAt; written last
    templates/                                 # stable copy; other tools point here [key]
    last-release                               # JSON record of the last attempt
    hold                                       # after a gate failure or rollback [temp]
    release.lock                               # only during a release [temp]
    staging/                                   # only during a release [temp]
```

## 2. What runs at runtime

`bin/relay` is a normal runtime with relay's code appended. An environment flag makes it behave as the plain runtime, and relay uses that to start its own children, so **a release does not need a separate runtime on `PATH`**.

The preview server compiles native code, so the release must carry `node_modules` with the binding for its OS and CPU. That is the main reason there is no single-file build.
