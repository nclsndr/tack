# Tables, relations and roles in parcel-hub

One Postgres database, `parcel_hub`, holds three schemas: `public` for application data, `auth` for Better Auth and `ops` for control-plane records. Pick a role in Fig. 1 to see what it may read or write; tables it may not touch are hatched.

`public` holds application data. Everything hangs off `depots.code`: docks, parcels and temperature readings each reference it. `dock_id` and `weight_kg` start empty and are filled by enrichment.

`ops.audit_events.actor_id` is the only key that leaves its schema: an audit row names a user in `auth`. `ops.job_logs` and `ops.audit_events` share a Temporal workflow ID with no foreign key between them.
